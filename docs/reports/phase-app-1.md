## What we learned (inputs to Step 2)

| Finding | Consequence |
|---|---|
| DimXpert sizes and ± values come back in **mm**; geometric tolerances (`IDimXpertTolerance.Tolerance`) in **µm** (0.02 → 20); face geometry (`IFace2`) in **metres, part coordinates** | The reader converts each one explicitly, and a test pins each conversion. Face positions get the component transform (`IComponent2.Transform2`); my first gap check forgot it and gave 61 mm instead of 1. |
| A DimXpert Width gives its two faces directly (`Feature.GetFaces`) | Exactly the face pair the chain builder needs. |
| Drawing dimensions attach to view **edges**; each edge's two adjacent faces include the dimensioned face | Rule: the dimensioned faces are the adjacent faces *not shared* by the two edges, and they must be parallel. This gives part coordinates; the drawing's referenced model (`IView.GetReferencedModelName`) says which part. |
| **STEP AP242 with 3D PMI is not available here.** The AP242 setting was accepted, but SolidWorks wrote AP203 (`CONFIG_CONTROL_DESIGN`) with no PMI. AP214 export works. No MBD add-in is installed. | For this maintainer, the SolidWorks API is the only automatic route. The STEP PMI path stays for users of other CAD tools. **Likely, not proven:** AP242 + PMI needs the MBD licence. |
| The ISO 2768 general class could **not** be read: `GetBlockTolerances` raises "write-only property"; preference 408 reads 1 in every part, including ones never set | Open item 1 below. Until it's solved, the app asks for the class (it's in the plan's table anyway). |
| The API cannot *edit* a DimXpert tolerance (`SetValues2` returns False); setting the DimXpert document defaults before inserting works | Only matters for making test files; detectTOL only reads. |
| `DimXpertManager(config, False)` reads without creating a DimXpert schema | detectTOL must never modify the user's file: always pass False and never save. |
| Late-bound COM cannot see the DimXpert methods; typed wrappers (`gencache.EnsureModule` on `sldworks.tlb` / `swdimxpert.tlb`, GUIDs in `swlib.py`) work | Step 2 uses typed wrappers. |

## Known limitations / open risks

- Only DimXpert **Width** (size between two parallel faces), Flatness and drawing linear dimensions were tested. Untested: DimXpert *DistanceBetween* (location), fit codes (`LimitsAndFitsCode`), datums, parallelism, and assemblies with rotated components (only identity rotations so far).
- Only one assembly, generated by script. Real engineer-made models (sketch dimensions, mirrored parts, configurations, sub-assemblies) are Step 5.
- The assembly in `examples/solidworks/` references its parts by the folder it was built in (Desktop). SolidWorks normally finds parts next to the assembly too; Step 2 tests will confirm this.
- Opening a file needs a SolidWorks licence. Every analysis costs about 20 s of SolidWorks time, which the app has to show as progress.
